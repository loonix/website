1. State Management Pattern

The Problem: Saving state only on success causes infinite loops when tasks fail.

❌ WRONG (Asymmetric) 
fn execute_task(task: Task) -> Result<()> {
    match do_work(&task) {
        Ok(output) => {
            state.mark_complete(&task);
            state.save()?;  // ← Only saves on success
        }
        Err(e) => {
            log::error!("Failed: {}", e);
            // ← No save! State not persisted!
        }
    }
}
✅ CORRECT (Symmetric) 
fn execute_task(task: Task) -> Result<()> {
    match do_work(&task) {
        Ok(output) => {
            state.mark_complete(&task);
            state.save()?;  // Save on success
        }
        Err(e) => {
            state.track_failure(&task, &e);
            state.save()?;  // ← ALSO save on failure!
        }
    }
}

Key Pattern:

// ALWAYS save state in both branches
match result {
    Ok(_) => { state.update(); state.save(); }
    Err(_) => { state.update(); state.save(); }  // ← Don't forget!
}

2. Validation Pattern

The Problem: Marking tasks complete without checking if output is actually correct.

❌ WRONG (No Validation) 
async fn create_component(name: &str)
    -> Result<()> {
    let code = llm.generate(name).await?;
    fs::write(
        format!("{}.svelte", name),
        code
    )?;

    // ← Assumes file is good!
    Ok(())  // Marked as success
}
✅ CORRECT (With Validation) 
async fn create_component(name: &str)
    -> Result<()> {
    let code = llm.generate(name).await?;
    let path = format!("{}.svelte", name);
    fs::write(&path, &code)?;

    // ← VALIDATE before declaring success
    validate_component(&path)?;

    Ok(())
}

Validation Function Example:
